# 开发历程

这个项目不是一次性设计的——每一段架构都是被真实问题逼出来的。下面按时间线记录几个关键节点：问题是什么、根因在哪、修完留下了什么机制。

## 事故驱动的安全修复

**XSS 事故**：Markdown 渲染组件历史上默认允许原始 HTML 且没有消毒，匿名访客在评论区提交 `<img onerror=...>`，管理员浏览文章时即触发，可偷走 localStorage 里的 JWT。

修复不是打个补丁了事，而是固化成一条红线：

- 渲染器默认 `allowHtml=false`；只有作者本人写的文章正文才允许受控富媒体，且仍过 `rehype-sanitize` 白名单消毒
- 评论、论坛、聊天、提示词等一切用户可提交内容，一律禁 HTML
- 新增渲染场景（如聊天气泡的 Markdown）默认继承安全配置

## 后台 AI 助手：从「完全不可用」到工作台

助手最初**打开就 500**——三个根因叠加：内部回环调用走了错误端口、路径拼接吃掉尾斜杠、参数经 shell 传递时 JSON 转义被破坏。逐个修复后重写了整个前端界面（会话列表、消息工具卡片、过程流、校验过的工具结果渲染），并把这三类故障写进了回归清单。

这一轮的教训：**"AI 能用"和"AI 的每个工具都能用"是两回事**——助手靠统计技能就能回答日常问题，而文章类操作全坏着，且不报错。

## 一个静默 bug 引出的契约测试

给助手扩技能前做了一次 API 盘点，发现文章技能带着三个**静默 bug**：

| 传参 | 后端实际 | 后果 |
| --- | --- | --- |
| `keyword=` | 路由参数叫 `search` | FastAPI 静默忽略，**搜索永远返回全量** |
| `content=`（建文） | 必填字段叫 `content_md` | 建文必 422 |
| `content=`（改文） | 同上 | Pydantic 吞掉未知字段，**改正文"以为改了其实没改"** |

三个都不抛异常——AI 拿着错误结果继续编答案。修复后我们把这类契约固化成 26 用例的自检（详见 [AI 架构](/ai-architecture)），并验证过它真的能抓 bug：往代码里注入这三个原版 bug，自检全部报警，报错信息直接指到问题字段。

**教训**：薄封装的参数名必须对着路由签名抄；写完技能要「逐个真实调用一次」，而不是看到没报错就算过。

## 一次自己造成的线上事故

一次排查数据库锁问题时，往 FastAPI 的 `get_db` 依赖里加了 `rollback()`——结果流式响应的依赖清理时机把还在使用的 ORM 对象踢出了会话，线上助手开始抛 `DetachedInstanceError`。而最初的"数据库锁"根本不是产品 bug，是测试容器连错了库。

**教训**：为一次性、由自己操作造成的故障去改核心依赖，是这两次线上问题的共同根源。回滚改动、改用局部变量持有会话数据，并在文档里立了规矩。

## 技能扩充：54 个技能与导航型工具

助手从 24 个技能扩到 **54**（热点日报、论坛、批量操作、用户管理此前完全没接）；看板娘从 5 个检索工具扩到 **9**，补上了「你们都写什么」「最近更新了什么」这类导航问题她答不了的缺口。同期两个工程决策：

- **批量操作放技能层**：后端没有接受 ID 列表的端点，与其为了 AI 加一批后端路由，不如在技能层做循环+汇总（单条失败不中断，失败明细如实回报）
- **给模型的返回要裁剪**：接口为前端设计（一次给全），给模型用必须在技能层收着点——一个分面接口实测 7.8 万字符，直接塞给模型会撑爆上下文

## 部署演进：手工脚本 → CI/CD

| 阶段 | 形态 | 痛点 |
| --- | --- | --- |
| 早期 | 本地构建、手工上传 | 上传报成功但服务器留旧包（踩过两次），靠 md5 校验兜底 |
| 中期 | 半自动脚本 | 部署快了，但仍然"谁记得跑脚本谁负责"，GitHub 只是代码镜像 |
| 现在 | **GitHub Actions CI/CD** | push 即检查（含 26 用例契约自检）→ 通过自动部署 → 失败自动回滚，生产镜像随 CI run 编号 |

CI/CD 上线本身就是一次方法论验证：检查在 GitHub runner 首跑即绿；首次部署在 SSH 密钥环节失败（一个挺隐蔽的管道行尾污染问题），但失败没有影响生产——**这正是自动部署该有的失败模式：炸在部署前，而不是炸在生产上**。

## 贯穿始终的三条纪律

1. **证据优先**：没有跑过验证、看过输出，不说"完成"。本文档站里的每个数字（54 技能、26 用例、78K→21K）都是实测过的。
2. **契约测试挡人肉**：凡是"不报错只是结果不对"的接口类 bug，一律固化成可重复执行的检查，接进 CI。
3. **失败要能自己回家**：部署有回滚容器，替换有备份目录，CI 失败不影响生产——炸在部署前是设计的一部分。
